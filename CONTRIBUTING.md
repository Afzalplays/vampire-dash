# Contributing

Thanks for helping build Vampire Dash.

1. Open an issue describing bugs or proposed features before large changes.
2. Keep pull requests focused and update documentation when configuration changes.
3. Never commit credentials, customer data, private keys, database dumps or real payment payloads.
4. Add tests for authentication, authorization, billing and resource enforcement.
5. Do not mark a feature complete until backend enforcement and tests exist.
6. Avoid arbitrary shell execution paths and unsafe filesystem access.

Use conventional commit messages where practical, such as feat(auth): add TOTP enrollment.
